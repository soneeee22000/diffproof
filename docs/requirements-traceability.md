# Requirements traceability

- Status: planning (v0 + amendment A1, 2026-11-17). No requirement is met yet; every row is planned.
- Source of truth for requirement **text** is `docs/SPEC.md` §14. This file adds interpretation, planned evidence and
  verification type.
- 65 requirements (60 at A0; A1 added FR-19, SEC-09, EVAL-08, EVAL-09 and EVAL-10).

**ID scheme.** `FR` functional · `GATE` deterministic gate and detectors · `SEC` security · `NFR` non-functional ·
`EVAL` evaluation · `CON` constraint · `DEL` deliverable. IDs are stable; a changed requirement keeps its ID and gets an
amendment tag (`[A1]`) pointing to SPEC §15.

**Verification types.** `automated test` (a pytest node carrying `@pytest.mark.req("<ID>")`) · `automated check script`
(a CI step that fails the build) · `eval metric` (a number in `docs/RESULTS.md`, generated by code) · `manual review`
(a URL or file named in the Evidence column).

**Enforcement (from G1).** `scripts/trace_check.py` (NFR-09) parses this table and the `req` markers in `tests/`. CI fails
when an `automated test` row has no marked test, when a marker names an unknown ID, or when a `manual review` row has no
evidence. Moving a row to "met" happens on the gate's exit checklist, with a commit SHA.

**What a marker proves.** A marker shows that a test for the requirement exists. It does not show the requirement is
met; that judgement is made on the gate's exit checklist, against the evidence named there. [A1]

## Ambiguities and the interpretation chosen

- **"Returned to the agent" evidence (GATE-02).** A line counts only if a tool call in the producing agent's own trace
  returned it with its line number and side. Lines the model quotes from memory, from the PR description, or from
  another agent's results do not count.
- **"Changed function", "public definition", "changed public signature" (FR-03, FR-06, FR-07).** One definition each,
  in SPEC §4.3 and `domain/definitions.py`. Deleted functions are out of scope for test generation.
- **"Bug span" (EVAL-05).** The new-side lines of the AST node the mutation operator changed. A finding overlaps the
  bug if its location falls inside that span. No fuzzy tolerance. Overlap is spatial, not proof of a correct comment.
- **Executed (FR-09).** A test executed on a tree when every run's outcome there was `PASSED` or `FAILED`. Collection
  errors, setup errors, timeouts, empty runs and skips are not execution; the verdict table in SPEC §7.6 says how each
  combination is labelled.
- **Flaky (FR-09).** Any disagreement across `FLAKE_RUNS` runs on the same tree.
